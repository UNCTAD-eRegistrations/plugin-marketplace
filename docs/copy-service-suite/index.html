A new way of working

This guide introduces how we will increasingly automate recurring eRegistrations work, and the new notions we will use to do it: skills, country files, suites, and human-agent teamwork.

What is a skill?

A skill is an instruction, written in ordinary language. It is programming in human language: the agent reads it and turns it into actions with the tools available.

What is the country file?

It is the shared memory for humans and agents. The country file gathers what the team and the agents need to know about a country: how instances, services and GDBs are organized, what decisions were made, and what was learned during previous runs.

Skills update it as they work, and the team can edit it directly to add notes or context.

Why a suite?

Some work is too large for one skill. A suite groups several skills so the lead skill can call a specialist skill when a specific question appears.

What changes for the team?

We keep the judgement. The agent handles the repeatable work: reading context, checking systems, calling tools, preparing decisions and executing approved steps. After each run, it reports what happened and captures lessons for the next version.

Where will skills be available?

All skills will be published in the eRegistrations plugin marketplace, where they will be organized and managed by Mehdi.

Purpose of the “copy service on top of existing service” skill

The Copy service suite is a first example of this approach. It helps us copy existing services from one eRegistrations instance on top of the same services in another instance, while protecting service IDs, GDBs, BOT references and rollback options.

We use this especially during upgrades. For example, when moving an instance from eR 2.13 to 2.18, we can copy services to an instance already running the new version, test and fix them there, then import them back so the upgrade can happen with less risk. Roxana has developed a separate upgrade skill for the instance upgrade itself.

How the skill works

The lead skill guides the operator through the whole operation: choose the country, choose the instances, select the services, resolve GDBs, merge the services, verify the destination instance, and leave a report.

Une nouvelle façon de travailler

Ce guide présente la manière dont nous allons progressivement automatiser le travail récurrent d’eRegistrations, ainsi que les nouvelles notions que nous utiliserons pour le faire : skills, dossiers pays, suites et travail conjoint entre humains et agents.

Qu’est-ce qu’un skill ?

Un skill est une instruction, écrite en langage courant. C’est programmer en langage humain : l’agent la lit et la transforme en actions avec les outils disponibles.

Qu’est-ce que le dossier pays ?

C’est la mémoire partagée des humains et des agents. Le dossier pays rassemble ce que l’équipe et les agents doivent savoir sur un pays : l’organisation des instances, des services et des GDBs, les décisions prises et les leçons tirées des exécutions précédentes.

Les skills le mettent à jour pendant leur travail, et l’équipe peut le modifier directement pour ajouter des notes ou du contexte.

Pourquoi une suite ?

Certains travaux sont trop larges pour un seul skill. Une suite regroupe plusieurs skills afin que le skill principal puisse appeler un skill spécialisé lorsqu’une question précise apparaît.

Qu’est-ce qui change pour l’équipe ?

Le jugement reste humain. L’agent prend en charge le travail répétitif : lire le contexte, vérifier les systèmes, appeler les outils, préparer les décisions et exécuter les étapes approuvées. À la fin, il rend compte et garde les leçons pour la version suivante.

Où les skills seront-ils disponibles ?

Tous les skills seront publiés dans le marketplace de plugins eRegistrations, où ils seront organisés et gérés par Mehdi.

Objectif du skill « copier un service par-dessus un service existant »

La Copy service suite est un premier exemple de cette approche. Elle aide à copier des services existants depuis une instance eRegistrations par-dessus les mêmes services dans une autre instance, tout en protégeant les IDs de service, les GDBs, les références BOT et les options de restauration.

Nous l’utilisons surtout pendant les mises à jour. Par exemple, pour passer une instance de eR 2.13 à 2.18, nous pouvons copier les services vers une instance où la nouvelle version fonctionne déjà, les tester et les corriger là-bas, puis les réimporter afin que la mise à jour se fasse avec moins de risque. شیوه‌ای نوین در کار

این راهنما نحوه خودکارسازی فزاینده کارهای تکراری eRegistrations و مفاهیم جدیدی را معرفی می‌کند که برای این منظور استفاده خواهیم کرد: مهارت‌ها، فایل‌های کشور، مجموعه‌ها، و همکاری انسان و عامل هوشمند.

مهارت چیست؟

مهارت یک دستورالعمل است که به زبان عادی نوشته شده است. برنامه‌نویسی به زبان انسانی است: عامل هوشمند آن را می‌خواند و با ابزارهای موجود به اقدامات تبدیل می‌کند.

فایل کشور چیست؟

حافظه مشترک برای انسان‌ها و عوامل هوشمند است. فایل کشور آنچه را که تیم و عوامل هوشمند باید درباره یک کشور بدانند گردآوری می‌کند: نحوه سازمان‌دهی نمونه‌ها، سرویس‌ها و GDB‌ها، تصمیمات اتخاذ‌شده، و آموخته‌های اجراهای قبلی.

مهارت‌ها آن را حین کار به‌روزرسانی می‌کنند، و تیم می‌تواند مستقیماً آن را ویرایش کرده و یادداشت یا زمینه اضافه کند.

چرا مجموعه؟

برخی کارها برای یک مهارت بیش از حد بزرگ هستند. یک مجموعه چند مهارت را گروه‌بندی می‌کند تا مهارت اصلی بتواند هنگام ظهور یک سؤال خاص، مهارت متخصص را فراخوانی کند.

چه چیزی برای تیم تغییر می‌کند؟

قضاوت همچنان بر عهده ما است. عامل هوشمند کارهای تکرارپذیر را انجام می‌دهد: خواندن زمینه، بررسی سیستم‌ها، فراخوانی ابزارها، آماده‌سازی تصمیمات و اجرای مراحل تأیید‌شده. پس از هر اجرا، آنچه اتفاق افتاده را گزارش می‌دهد و درس‌هایی را برای نسخه بعدی ثبت می‌کند.

مهارت‌ها کجا در دسترس خواهند بود؟

همه مهارت‌ها در بازار پلاگین‌های eRegistrations منتشر خواهند شد، جایی که توسط مهدی سازمان‌دهی و مدیریت می‌شوند.

هدف مهارت «کپی سرویس روی سرویس موجود»

مجموعه Copy service suite نمونه‌ای اولیه از این رویکرد است. به ما کمک می‌کند سرویس‌های موجود را از یک نمونه eRegistrations روی همان سرویس‌ها در نمونه دیگر کپی کنیم، در حالی که شناسه‌های سرویس، GDB‌ها، ارجاعات BOT و گزینه‌های بازگردانی حفظ می‌شوند.

ما از این مجموعه به‌ویژه هنگام ارتقا استفاده می‌کنیم. مثلاً هنگام انتقال یک نمونه از eR 2.13 به 2.18، سرویس‌ها را به نمونه‌ای کپی می‌کنیم که نسخه جدید قبلاً روی آن اجرا می‌شود، آنها را آنجا آزمایش و رفع عیب می‌کنیم، و سپس آنها را بازمی‌گردانیم تا ارتقا با ریسک کمتری انجام شود. روکسانا یک مهارت ارتقا جداگانه برای ارتقای خود نمونه توسعه داده است.

ما هي المهارة؟

المهارة هي تعليمات مكتوبة بلغة عادية. إنها برمجة بلغة بشرية: يقرأها الوكيل ويحوّلها إلى إجراءات باستخدام الأدوات المتاحة.

ما هو ملف البلد؟

ذاكرة مشتركة بين البشر والوكلاء. يجمع ملف البلد ما يحتاج الفريق والوكلاء معرفته عن بلد ما: كيفية تنظيم البيئات والخدمات وقواعد بيانات GDB، والقرارات المتخذة، والدروس المستفادة من عمليات التنفيذ السابقة.

تقوم المهارات بتحديثه أثناء العمل، ويمكن للفريق تحريره مباشرة وإضافة ملاحظات أو سياق.

لماذا حُزْمة؟

بعض المهام أكبر من أن تتولاها مهارة واحدة. تجمع الحُزْمة عدة مهارات معًا بحيث يمكن للمهارة الرئيسية استدعاء المهارة المتخصصة عند ظهور سؤال محدد.

ما الذي يتغير بالنسبة للفريق؟

يبقى الحكم مسؤوليتنا. يتولى الوكيل المهام القابلة للتكرار: قراءة السياق، فحص الأنظمة، استدعاء الأدوات، إعداد القرارات وتنفيذ الخطوات المعتمدة. بعد كل تنفيذ، يقدّم تقريرًا عمّا حدث ويسجّل الدروس للنسخة التالية.

أين ستكون المهارات متاحة؟

ستُنشر جميع المهارات في سوق إضافات eRegistrations، حيث ينظّمها ويديرها مهدي.

Ένας νέος τρόπος εργασίας

Αυτός ο οδηγός παρουσιάζει πώς θα αυτοματοποιούμε ολοένα και περισσότερο τις επαναλαμβανόμενες εργασίες στο eRegistrations, και τις νέες έννοιες που θα χρησιμοποιούμε: skills, αρχεία χώρας, suites και συνεργασία ανθρώπου-πράκτορα.

Τι είναι ένα skill;

Ένα skill είναι μια οδηγία γραμμένη σε καθημερινή γλώσσα. Είναι προγραμματισμός σε ανθρώπινη γλώσσα: ο πράκτορας το διαβάζει και το μετατρέπει σε ενέργειες με τα διαθέσιμα εργαλεία.

Τι είναι το αρχείο χώρας;

Είναι η κοινή μνήμη για ανθρώπους και πράκτορες. Το αρχείο χώρας συγκεντρώνει όσα χρειάζεται η ομάδα και οι πράκτορες να γνωρίζουν για μια χώρα: πώς είναι οργανωμένα τα instances, οι υπηρεσίες και οι GDB, ποιες αποφάσεις λήφθηκαν και τι έγινε σε προηγούμενες εκτελέσεις.

Τα skills το ενημερώνουν καθώς εργάζονται, και η ομάδα μπορεί να το επεξεργαστεί απευθείας για να προσθέσει σημειώσεις ή πλαίσιο.

Γιατί suite;

Κάποιες εργασίες είναι πολύ μεγάλες για ένα skill. Ένα suite ομαδοποιεί πολλά skills ώστε το κύριο skill να μπορεί να καλέσει ένα εξειδικευμένο skill όταν εμφανιστεί ένα συγκεκριμένο ζήτημα.

Τι αλλάζει για την ομάδα;

Εμείς κρατάμε την κρίση. Ο πράκτορας αναλαμβάνει την επαναληπτική εργασία: διαβάζει πλαίσιο, ελέγχει συστήματα, καλεί εργαλεία, προετοιμάζει αποφάσεις και εκτελεί εγκεκριμένα βήματα. Μετά από κάθε εκτέλεση, αναφέρει τι έγινε και καταγράφει διδάγματα για την επόμενη έκδοση.

Πού θα είναι διαθέσιμα τα skills;

Όλα τα skills θα δημοσιευτούν στο eRegistrations plugin marketplace, όπου θα οργανώνονται και θα διαχειρίζονται από τον Mehdi.

Σκοπός του skill “αντιγραφή υπηρεσίας πάνω σε υπάρχουσα υπηρεσία”

Το Copy service suite είναι ένα πρώτο παράδειγμα αυτής της προσέγγισης. Μας βοηθά να αντιγράψουμε υφιστάμενες υπηρεσίες από ένα instance του eRegistrations πάνω από τις ίδιες υπηρεσίες σε άλλο instance, προστατεύοντας τα αναγνωριστικά υπηρεσιών, τις GDB, τις αναφορές BOT και τις επιλογές αναίρεσης.

Το χρησιμοποιούμε ιδιαίτερα κατά τις αναβαθμίσεις. Για παράδειγμα, όταν μετακινούμε ένα instance από eR 2.13 σε 2.18, μπορούμε να αντιγράψουμε υπηρεσίες σε ένα instance που ήδη τρέχει τη νέα έκδοση, να τις δοκιμάσουμε και να τις διορθώσουμε εκεί, και στη συνέχεια να τις επαναφέρουμε ώστε η αναβάθμιση να γίνει με λιγότερο ρίσκο. Η Roxana έχει αναπτύξει ένα ξεχωριστό upgrade skill για την ίδια την αναβάθμιση του instance.

Πώς λειτουργεί το skill

Το κύριο skill καθοδηγεί τον χειριστή σε όλη τη διαδικασία: επιλογή χώρας, επιλογή instances, επιλογή υπηρεσιών, επίλυση GDB, συγχώνευση υπηρεσιών, επαλήθευση του instance προορισμού και δημιουργία αναφοράς.

Επίλυση ανά GDB

Ισχύει μία από τις παρακάτω περιπτώσεις:

Η GDB λείπει από τον προορισμό

Το gdb copy την δημιουργεί (ίδιο όνομα, ίδιο σχήμα). Αντιγράφει δεδομένα από την προέλευση αν χρειάζεται.

Ίδια δομή, ίδιο όνομα, ίδια έκδοση

Δεν χρειάζεται καμία ενέργεια.

Ίδια δομή, ίδιο όνομα, διαφορετική έκδοση

Δεν χρειάζεται εργασία στην GDB. Μετά την εισαγωγή: το bot_update αντιστοιχεί τα BOT στην έκδοση του προορισμού.

Ίδια δομή, διαφορετικό όνομα

Δεν χρειάζεται εργασία στην GDB. Μετά την εισαγωγή: το bot_update αντιστοιχεί τα BOT στο όνομα + έκδοση του προορισμού.

Διαφορετική δομή

Το gdb copy λαμβάνει field_map από το compare.

Εμφανίζει στον χρήστη: σχέδιο μεταφοράς με αντιστοίχιση πεδίων + πεδία που θα χάσουν δεδομένα.

Ρωτά: αποδοχή / τροποποίηση / ακύρωση;

Δημιουργεί νέα έκδοση GDB στον προορισμό με το σχήμα της προέλευσης. Μεταφέρει δεδομένα προορισμού (παλιά → νέα έκδοση) με μετασχηματισμό πεδίων.

Εμφανίζει αποτελέσματα + δείγματα εγγραφών.

Μετά την εισαγωγή: το bot_update αντιστοιχεί τα BOT στη νέα έκδοση προορισμού.

Μην προχωρήσετε στη συγχώνευση έως ότου επιλυθούν όλες οι GDB. Ενημερώνει το αρχείο χώρας με τις αποφάσεις GDB και τα αποτελέσματα σύγκρισης.

Φάση συγχώνευσης

Ανά επιλεγμένη υπηρεσία

Αντίγραφο ασφαλείας, έλεγχος, εισαγωγή, ενημέρωση
Αντίγραφο ασφαλείας

Αποθηκεύει πλήρες στιγμιότυπο της υπηρεσίας προορισμού πριν από οποιαδήποτε αλλαγή. Αν κάτι πάει στραβά, αυτό το στιγμιότυπο επαναφέρει την υπηρεσία ακριβώς όπως ήταν.

Έλεγχος δημοσίευσης

Αν η υπηρεσία προορισμού είναι δημοσιευμένη, είναι ενεργή. Πολίτες και υπάλληλοι μπορεί να τη χρησιμοποιούν. Ρωτά: συγχώνευση σε αυτή την ενεργή υπηρεσία; (Ιδανικά αποδημοσιεύστε πρώτα ή κάντε το σε περίοδο συντήρησης.)

Εισαγωγή

Εκτελεί το service_import_on_top.

Ενημέρωση Bot

bot_update για κάθε BOT όπου το όνομα ή η έκδοση της προέλευσης διαφέρει από τον προορισμό.

Επαληθεύει: διατήρηση αναγνωριστικού υπηρεσίας, καταγραφή ελέγχου. Ενημερώνει το αρχείο χώρας.

Επαλήθευση

Ελέγχει ολόκληρο το instance προορισμού, όχι μόνο τις υπηρεσίες που τροποποιήθηκαν — μια αλλαγή σε GDB μπορεί να χαλάσει τα BOT άλλης υπηρεσίας.

Για κάθε BOT, επαληθεύει ότι το όνομα + έκδοση της GDB υπάρχει στον προορισμό.
